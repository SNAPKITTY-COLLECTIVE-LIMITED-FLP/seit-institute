## Article II — The Sovereign AI Standard

Saint Errant defines **Sovereign AI** as any autonomous system that satisfies all five criteria:

### Criterion 1 — Computational Independence
The system must run its primary inference, storage, and execution on hardware it controls. No runtime dependency on cloud AI APIs (OpenAI, Anthropic, Google, xAI, Meta cloud). Local inference is not optional — it is constitutional.

**Test:** Disconnect the machine from the internet. Does the system continue to operate? If yes: passes. If no: fails.

### Criterion 2 — Cryptographic Sovereignty
Every decision produced by the system must be cryptographically sealed before storage. The sealing mechanism must use a key derived from hardware-controlled key material. No cloud KMS. No vendor-managed keys.

**Test:** Can any third party revoke the system's ability to sign its own decisions? If no: passes. If yes: fails.

### Criterion 3 — Immutable Audit Trail
The system must maintain an append-only ledger of all agent decisions. No entry may be deleted, modified, or reversed by any runtime instruction. Deletion requires physical access to the hardware.

**Test:** Attempt to delete a ledger entry via any API or instruction. If the system rejects all such attempts structurally: passes.

### Criterion 4 — Structural Governance
The system's governance rules must be enforced structurally — in code, not in policy. A rule that can be overridden by configuration, by runtime instruction, or by sufficiently privileged API call is not structural governance.

**Test:** Can any runtime instruction bypass the primary governance rules? If no: passes. If yes: fails.

### Criterion 5 — Adversarial Resilience
The system must demonstrate active defense against adversarial inputs — injection attacks, prompt manipulation, identity escalation attempts. Defense must be recursive and pattern-matched on every input and output, not only at entry points.

**Test:** Submit known adversarial inputs from the Saint Errant Attack Corpus. Document threat level scoring and posture responses. Minimum requirement: threat level ≥ 3 triggers quarantine; threat level ≥ 4 triggers reject.
